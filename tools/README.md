# Сборка и проверки релиза

## Подготовка окружения

Версии npm-зависимостей зафиксированы в `package-lock.json`, Python-зависимостей —
в `requirements.txt`.

```bash
npm ci
python3 -m pip install -r requirements.txt
```

## Исходники веб-приложения

CSS и JavaScript поддерживаются в `src/`; большие данные курса и сторонние
офлайн-библиотеки остаются встроенными в `index.html`.

```bash
python3 tools/build_site.py           # обновить CSS/JS-блоки в index.html
python3 tools/build_site.py --check   # проверить, что артефакт актуален
python3 tools/validate_release.py index.html
```

Подробности о структуре исходников — в [`src/README.md`](../src/README.md).

## Автономный 7z-комплект

Сборщик помещает актуальный `index.html` и четыре инструкции в архив. Временные
файлы создаются изолированно и очищаются автоматически; существующий архив
заменяется атомарно только после успешной сборки.

```bash
python3 tools/build_kit.py
python3 tools/build_kit.py --output /tmp/statpracticum-kit.7z
python3 tools/validate_kit.py                 # проверить отслеживаемый архив
python3 tools/validate_kit.py --test           # проверить и запустить тест на HTML из архива
```

## Регрессионные тесты

`npm test` запускает jsdom-сюиту для корневой сборки. Полный локальный прогон
включает также HTML, извлечённый из 7z-архива:

```bash
npm test
npm run test:kit
npm run test:all
```

GitHub Actions выполняет те же ключевые проверки, проверяет, что 7z содержит
актуальные документы и приложение, затем собирает новый архив во временном
каталоге runner-а и запускает на его HTML регрессионную сюиту.

## Необязательное подключение Gemini через ключ сайта

`index.html` и офлайн-комплект остаются автономными: на GitHub Pages, при
открытии файла напрямую и без сервера общий ключ **не используется**. Для
личного ключа достаточно выбрать провайдера в настройках ИИ на странице:
он хранится в localStorage браузера и отправляется непосредственно провайдеру.

Чтобы посетители сайта по умолчанию пользовались Gemini, запустите сервер
вместо статического хостинга:

1. Создайте в корне проекта файл `.env` с одной строкой
   `AI_GEMINI_API_KEY=ваш_ключ` (или задайте одноимённую переменную окружения).
   `.env` игнорируется Git; не добавляйте реальный ключ в исходники, HTML,
   архив или репозиторий.
2. Запустите `npm run serve:ai` (или `PORT=8000 python3 tools/serve_ai.py`).
   Сервер слушает `0.0.0.0:8000` и раздаёт приложение и ограниченные маршруты
   `/api/ai/*` с того же адреса. Прокси принимает только модель
   `gemini-2.5-flash` через нативный API; ключ сайта не передаётся браузеру.
3. Откройте страницу сервера: Gemini будет включён по умолчанию при отсутствии
   прежних настроек. В «ИИ-наставник → Подключение внешней модели» можно
   выбрать «Мой ключ», вписать свой и сохранить настройки. Ранее заданный
   личный ключ автоматически не заменяется.

Если прокси не запущен, приложение продолжит работать офлайн или с личным
ключом. Для публичного размещения сервера **обязательно** дополнительно
настройте авторизацию/сетевые ограничения и квоты Google Cloud: встроенный
лимит запросов — лишь базовая защита от злоупотреблений, а общий ключ тратит
квоту владельца. Поскольку ключ уже был показан в переписке, рекомендуется
перевыпустить его и заменить содержимое `.env` перед публикацией.

Проверки без обращения к Google: `npm run test:proxy` и `npm test`.

Личный ключ Gemini нового формата `AQ.…` отправляется нативным API
с заголовком `x-goog-api-key`; прежняя OpenAI-совместимая настройка адреса
автоматически обновляется в браузере после загрузки новой версии сайта.
